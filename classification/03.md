# 03-AI推理与服务加速

## 顶层责任

模型推理、Serving、量化、调度、算子和编译

## 二级分类与边界

| 二级分类 | 范围与示例 |
| --- | --- |
| 请求与调度 | Cache亲和调度，SLO感知调度，Batching调度 |
| 模型计算 | 模型压缩 算子优化 通信优化 |
| KV Cache | 前缀匹配, Cache池化，KV量化 |
| 解码 | topP、toK、 投机推理 |
| 输入输出数据 | 输入裁剪，输出思维链裁剪 |
| 推理部署 | TP/DP/EP/PD分离 |

## 易混淆边界

以模型推理与服务性能为主体。KV机制归KV Cache，请求队列与批处理归调度；训练与推理共用的通用张量通信机制归基础竞争力。集群租户与设备资源池归云与AI基础设施。

## 已归档判例

- Invariant Bit Packing 无损张量压缩 → 03-AI推理与服务加速/模型计算：正文是CPU内存到GPU的ML推理张量压缩与即时解压，覆盖GNN/DLRM/LLM仍都属于模型推理；I2并不限LLM。原B2把主机内存供数过度泛化为分布式协调，建议改I2。
- GKE Inference Gateway Latency Source Understanding → 03-AI推理与服务加速/请求与调度：Endpoint Picker按前缀缓存、负载和LoRA选择实例，属于请求调度。
- Intel Xeon 6 + NVIDIA HGX B200 异构推理架构研究归档 → 03-AI推理与服务加速/推理部署：CPU小模型与GPU大模型联合提供推理服务，报告重点是异构部署。
- MiMo 与 TileRT 万亿参数 1000+ TPS 解码分析归档 → 03-AI推理与服务加速/解码：以万亿参数模型的1000+TPS解码及DFlash路径为研究中心。
- AcceptMoE：自调整专家集的 MoE 投机解码 → 03-AI推理与服务加速/解码：AcceptMoE优化投机解码验证器专家选择及权重搬运。
- 增量 BPE 分词算法实现 O(n log²t) 复杂度，推理吞吐提升 3 倍 → 03-AI推理与服务加速/输入输出数据：增量BPE改变推理输入的分词处理，而非模型本体；I5输入输出数据自然包括输入表示处理，例举的输入裁剪不构成白名单。
- KVarN 论文 Source Understanding → 03-AI推理与服务加速/KV Cache：KVarN研究低位KV缓存量化的误差归一化。
- RTPurboV2 实现稀疏注意力迁移 → 03-AI推理与服务加速/模型计算：通过少量后训练把既有全注意力模型迁移成低计算稀疏注意力路径，主要交付为模型计算压缩；后训练是实现手段，归I2。
- ICML 2026 Poster收录了Dustin论文 → 03-AI推理与服务加速/解码：Dustin优化长上下文投机解码的稀疏验证。
- Nexus Sampling KV Cache Eviction Evidence Board → 03-AI推理与服务加速/KV Cache：Nexus Sampling改变KV缓存驱逐与生存概率机制。
- CCN Report Archive → 03-AI推理与服务加速/请求与调度：SlidingServe围绕LLM请求调度与服务容量优化。
- SVF LLM Scheduling Evidence Board → 03-AI推理与服务加速/请求与调度：SVF以KV体积排序请求并分析延迟竞争比。
- RedKnot Long-Context LLM Serving → 03-AI推理与服务加速/KV Cache：Head-aware KV复用是被优化的直接对象，SegPagedAttention为实现配套；I3足够，不因兼有算子而待定。
- Prox：无需训练的 FFN 激活稀疏化 → 03-AI推理与服务加速/模型计算：Prox以代理权重选择FFN通道，减少权重访问与乘加。
- ReCo：奖励协调的高效推理 → 03-AI推理与服务加速/输入输出数据：过程奖励只提供控制信号，主要动作是反思token抑制和置信度早停并协同保留KV；直接压缩推理输出长度，归I5。
- BloomBee 互联网尺度分布式生成推理 → 03-AI推理与服务加速/推理部署：BloomBee联合层分配、微批、卸载及压缩实现互联网分布式推理。
- 稠密 LLM 并行化策略评测 → 03-AI推理与服务加速/推理部署：比较TP/PP部署的延迟吞吐和瓶颈，评测对象是推理部署策略而非通用模型能力，归I6。
- 长上下文并非免费｜安全提示词剪枝层工程报告 → 03-AI推理与服务加速/输入输出数据：安全提示词剪枝层直接压缩模型请求输入上下文，I5输入裁剪为明确承接项，Agent上下文用途不构成分类疑问。
