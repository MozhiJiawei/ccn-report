Running Subagents in the Background

Why

复杂 agent 不适合把所有工作分支都阻塞在主对话里，尤其是研究、检索、代码检查这类耗时工作会拖慢交互。

What

文章介绍 background subagents：主 agent 可以派发并行分支，让子 agent 在后台运行，再把结果汇总回主流程。

How

通过调度、状态跟踪、结果回收和上下文隔离，background subagents 让深度 agent 在保持用户交互的同时处理耗时分支。

Thesis

这篇文章的关键不是并行本身，而是后台分支、独立上下文和结果汇合这三个控制点。

Why: 复杂 agent 不适合把所有工作分支都阻塞在主对话里，尤其是研究、检索、代码检查这类耗时工作会拖慢交互。 What: 文章介绍 background subagents：主 agent 可以派发并行分支，让子 agent 在后台运行，再把结果汇总回主流程。 How: 通过调度、状态跟踪、结果回收和上下文隔离，background subagents 让深度 agent 在保持用户交互的同时处理耗时分支。

Evidence

后台 subagents 把耗时分支从主对话中移出，但结果仍回到主决策。

后台分支把等待时间从主循环移出去

主 agent 不必停下来等待所有分支完成，可以继续与用户或其他工具协作。这样对话体验和长时分析不会互相拖住。

独立上下文降低了并行工作的干扰

每个子 agent 承担明确工作，拥有自己的上下文和输出边界。主 agent 收到的是整理后的结果，而不是混杂的中间过程。

结果回收让并行工作重新进入决策

后台执行不是 fire-and-forget。主 agent 需要知道工作状态，在合适时间读取子工作结果，并把它纳入下一步规划。
