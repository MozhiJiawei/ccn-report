Why

Agent 失败常常藏在多步推理、工具调用、上下文和状态变化里，单看日志很难知道系统为什么偏离目标。

What

文章的核心判断是 observability 与 evaluation 在 agent 时代合并成同一套闭环：traces 同时支撑调试、测试、线上监控和事后洞察。

How

用 runs 捕获单步决策，用 traces 还原完整轨迹，用 threads 连接多轮上下文，再按 single-step、full-turn、multi-turn 与 offline、online、ad-hoc 粒度评估。

可观测性提供评价所需的事实底座

runs、traces、threads 分别记录单步调用、完整执行和多轮会话，让评价不再只依赖最终答案。

可观测性提供评价所需的事实底座

runs、traces、threads 分别记录单步调用、完整执行和多轮会话，让评价不再只依赖最终答案。

评价粒度要匹配 agent 行为粒度

single-step、full-turn、multi-turn evaluation 对应不同失败形态，避免用一个分数覆盖所有问题。

生产轨迹会长成下一轮测试集

真实 traces 可以进入离线数据集、线上监控和 ad-hoc 分析，把生产问题转化为可复现的改进材料。

这篇文章的论证链路

观察记录真实输入、输出、工具调用和上下文。
归纳把单次行为聚合成模式、失败类型或业务信号。
评价用 traces、datasets 或在线评分验证改动。
改进调整 prompt、工具、模型、memory 或 runtime。
