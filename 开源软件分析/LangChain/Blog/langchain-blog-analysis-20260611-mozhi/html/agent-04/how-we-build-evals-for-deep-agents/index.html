Why

Deep Agents 的行为由 evals 牵引；如果 eval 数据和指标不贴近生产行为，分数提升可能只是错觉。

What

文章介绍 LangChain 如何为 Deep Agents 构建 targeted evals：从 dogfooding、traces 和真实失败中取样，按行为分组，并用 LangSmith 共享 traces 反复分析。

How

团队先 catalog 生产中重要行为，再围绕文件检索、多步工具调用等行为写 eval；每次 eval run 都 trace 到 LangSmith，团队据此调整 prompt、tool description 或 harness。

一句话带走

Deep Agents evals 的原则是“直接测量关心的行为”。文章反对盲目堆大量测试，主张从 dogfooding、traces 和真实失败中取样，按行为分组，持续用 LangSmith trace 分析是否真的改善 agent。

文章真正强调的三件事

每个 eval 都会塑造 agent 行为

失败的 eval 往往会推动 prompt、tool description 或 harness 变化，因此 eval 选择本身很重要。

更多 eval 不等于更好 agent

不贴近生产行为的 suite 会制造“变好”的错觉，甚至诱导过拟合。

traces 让团队共同维护 eval 质量

所有 eval run 进入 LangSmith project，任何人都能查看失败、修复并重新判断 eval 是否有价值。

支撑观点的机制

Deep Agents 先定义生产行为

团队关注多文件检索、5+ tool calls sequence、文件系统使用等真实能力，而不是只追 benchmark 覆盖量。

数据来源包括 dogfooding 和 trace 阅读

内部使用 Deep Agents 与 Open SWE 时产生的失败和边界样例，成为 targeted eval 的高价值来源。

评测分组让改动更可解释

按行为分组后，团队能看出某个 harness 改动改善了哪个能力，也能发现它是否伤害了其他能力。
