Why

标准 agent loop 很简洁，但生产场景常需要 PII 检测、工具选择、上下文管理等应用特定逻辑；只改 prompt 和 tools 不够。

What

LangChain middleware 提供 hooks，让开发者在 agent harness 的关键步骤前后插入自定义逻辑，同时保留 create_agent 和 Deep Agents 的基础结构。

How

middleware 可以围绕 model call、tool call、state/context 处理等位置工作；Deep Agents 自身也通过 middleware 组合出 planner、filesystem、subagents 等能力。

一句话带走

middleware 把 agent harness 从固定黑盒变成可插拔系统。基础 loop 仍是 LLM 调工具，但生产 agent 可以在模型调用、工具执行和上下文处理前后插入 PII 检测、工具过滤、记忆或策略逻辑。

文章真正强调的三件事

harness 是模型和环境之间的系统

文章先把 agent 定义为模型周围的系统：数据、memory、tools、environment 都由 harness 连接。

middleware 处理 prompt/tools 之外的定制

当需求是“每次调用前做检查”或“工具输出后处理”，middleware 比改 prompt 更合适。

Deep Agents 本身就是 middleware 组合

Deep Agents 的规划、文件系统和 subagents 说明 middleware 不只是扩展点，也是复杂 harness 的组成方式。

支撑观点的机制

标准 loop 是共同底座

create_agent 提供 LLM in a loop calling tools 的核心结构。不同应用的差异主要出现在 loop 周围的策略与数据处理。

middleware 给定制逻辑明确位置

PII detection、tool selection、context management 等逻辑可以作为 middleware 加入，而不是散落在业务代码里。

复杂 harness 可以逐层组合

Deep Agents case study 显示，middleware 能把 filesystem、planning、subagents 和其他能力组合到同一个 agent loop。
