Why

LangChain 在一个月内基于 Deep Agents harness 发布了多个 agent 应用，随之需要给状态ful、会调用工具、会改文件的 agent 建立可靠评测。

What

文章总结了 5 个评测模式：每个 datapoint 需要定制测试逻辑，single-step 验证具体决策点，full turn 检查结束状态，multi-turn 模拟真实交互，可复现环境避免 flaky 结果。

How

作者把可测对象拆成 trajectory、final response 和 other state，并用 Pytest/Vitest、LangSmith traces、LangGraph interrupt、临时目录或请求录制回放来覆盖不同风险。

Deep Agent 的评测对象不止最终回答

文章把测试目标拆成工具轨迹、最终回复和其它状态。对会写文件、记忆偏好或生成工件的 agent 来说，成功标准经常落在状态变化和工具参数上。

单步、整轮和多轮对应不同失败形态

single step 像单元测试，适合抓下一次工具调用是否正确；full turn 看端到端结果；multiple turns 更接近真实用户，但需要每轮检查，偏离时提前失败。

环境可复现决定评测是否可信

Deep Agents 常依赖文件系统、外部 API 和长期状态。文章建议每个测试从干净目录、sandbox 或录制回放的请求开始，避免结果被外部状态拖偏。
