How Auth Proxy secures network access for LangSmith agent sandboxes

Why：sandbox 里的 agent 仍要联网和鉴权，直接把长期 secret 放进 runtime 会扩大泄露面。What：LangSmith Auth Proxy 把凭据注入和 egress policy 移到网络边界，让 agent 发普通请求，却读不到 API key。How：proxy 按目标 host/path 检查策略、注入 workspace_secret/plaintext/opaque headers，或通过 callback 获取短期凭据；异常时拒绝请求而不是无凭据放行。

Why

sandbox 里的 agent 仍要联网和鉴权，直接把长期 secret 放进 runtime 会扩大泄露面。

What

LangSmith Auth Proxy 把凭据注入和 egress policy 移到网络边界，让 agent 发普通请求，却读不到 API key。

How

proxy 按目标 host/path 检查策略、注入 workspace_secret/plaintext/opaque headers，或通过 callback 获取短期凭据；异常时拒绝请求而不是无凭据放行。

安全边界从 runtime 内部移到 outbound path。

agent 或 sandboxed code 发请求，Auth Proxy 检查目的地策略，再决定 block、allow 或 attach headers。凭据和访问规则不以环境变量或文件形式出现在 sandbox。

credential injection 降低多条泄露路径。

API key 不进入 runtime，就不容易被 prompt injection、恶意包、日志、文件写入或模型错误直接读走；agent 得到的是调用 API 的效果，不是凭据本身。

egress policy 让联网范围成为基础设施约束。

同一 proxy 可以限制只访问模型 API、GitHub 必要路径、内部 package mirror，或阻断不可信 registry。文章尤其强调 package install 与 curl pipe shell 的风险。

动态凭据让生产 auth 保持 user-scoped。

Fleet 场景里可以配置 callback：proxy 缺少缓存凭据时向团队的 endpoint 请求 header，支持短期 OAuth、per-user token、内部 auth service 和刷新流程。
