Why

生产 agent 可能反复使用错工具、参数错误、低效执行或漏用工具，单条 trace 难以变成系统改进。

What

LangSmith Engine 把 traces 中的 recurring failure 转成 issue board、evaluator、dataset example 和 fix proposal。

How

它在 sandbox 中运行，使用 LangSmith CLI 拉取 traces 和 issue 状态，借 subagents 先筛查压缩 trajectory、再深查可疑 trace，并用 Agent Overview 保留跨轮记忆。

Engine 的输出不是坏 trace，而是 issue。

issue 包含名称、描述、类别、严重度、证据 traces、proposed actions 和 tags。proposed actions 可以是 online evaluator、offline dataset examples 或 prompt/code fix。

四类输入让它理解项目状态。

Agent Overview 像活的 AGENTS.md，记录 agent 职责、trace 结构、失败模式和团队偏好；Engine 还读取 trace 项目、现有/关闭 issues，以及可选代码库。

架构把分析、执行和记忆分层。

Engine 在 LangSmith Sandbox 中工作，LangSmith CLI 负责 fetch/update，custom tools 用于测试 evaluator 和提出 regression examples，subagents 负责筛查与深查，Agent Overview 作为可编辑 memory。

trace volume 逼出了两阶段分析。

文章指出生产项目在 lookback window 里可能有数千到数万 traces，主 agent 不能加载所有完整内容。Engine 先用压缩 trajectory 做 broad screening，再只对可能有价值的 trace 加载 full context。
