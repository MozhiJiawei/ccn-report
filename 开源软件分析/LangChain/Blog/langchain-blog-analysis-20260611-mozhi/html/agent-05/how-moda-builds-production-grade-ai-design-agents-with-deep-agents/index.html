Moda 把设计 agent 做成了可迭代的产品工作台

Why: AI 做视觉设计的难点不是生成一张漂亮图，而是让非设计师在品牌、版式和多轮修改里保持控制。What: Moda 用 Deep Agents、LangSmith 和可编辑 2D 矢量画布，把专业级演示文稿、社媒图、手册和 PDF 变成可协作的 agent 工作流。How: 系统把工作分给设计、研究、品牌三类 agent，并通过自定义布局表示、动态技能与工具加载、按画布规模调节上下文来控制质量、成本和延迟。

Why视觉设计缺少像 Flexbox 一样适合模型推理的布局抽象。
WhatModa 的 AI 直接操作可编辑画布，而不是给出一次性静态输出。
HowDeep Agents 承载研究与品牌 agent，LangSmith 追踪每次执行。
5 秒核心

这篇案例把“生产级设计 agent”的关键拆开：不是更会画，而是更会理解上下文、调用合适技能、保持品牌一致，并把结果留在用户能继续编辑的画布上。

Moda 的差异来自“可编辑协作”，不是一次性生成

文章把 Moda 类比为带 Cursor 式 AI 侧栏的 Canva 或 Figma：agent 生成起点，用户继续选择、移动、缩放和改样式。

1

用户从“接受或拒绝”变成共同修改

文章强调 Moda 避开了 generate-and-replace 流程。AI 产出专业起点，用户保留对最终设计的控制权。

2

目标用户是需要快速产出品牌材料的非设计师

营销、创始人、销售和小企业主可以创建演示文稿、社媒内容、手册和 PDF，而不需要先学设计软件。

生产级质量依赖三类 agent 分工

Moda 的系统不是单个聊天机器人。文章描述了三个 agent 共享轻量 triage、主循环、动态上下文加载和 LangSmith tracing 的总体架构。

Design AgentCursor 式侧栏背后的主 agent，在画布上实时创建和迭代设计；当前运行在较早的自定义 LangGraph loop 上。
Research Agent基于 Deep Agents，从外部来源抓取并保存结构化内容，例如公司网站信息。
Brand Kit Agent基于 Deep Agents，摄取颜色、字体、logo、品牌语气、品牌书或旧 deck，让输出从一开始就贴合品牌。
Ravi Parikh 的核心判断很直接：PowerPoint XML 里的 XY 坐标适合保存数据，却不适合让 LLM 描述元素该放在哪里。

上下文工程把“会生成”推进到“可稳定上线”

文章的技术重心在上下文表示、缓存、工具数量和画布规模控制。它们共同决定输出质量，也决定成本和延迟。

用自定义 DSL 替代原始画布状态

原始 canvas state 充满坐标、冗长且耗 token。Moda 给 agent 更紧凑、更接近布局抽象的表示层。

先 triage，再注入技能

轻量 Haiku 模型先识别输出格式，再预载包含设计最佳实践和格式规范的 Markdown skills。

工具按需激活

核心上下文保留 12-15 个工具，约 30 个额外工具通过 RequestToolActivation 在特殊需求出现时加载。

画布越大，上下文越分层

小画布给完整状态，大型项目给高层摘要，并允许 agent 通过工具拉取细节，把 token 使用控制在边界内。

LangSmith 是 Moda 的工程反馈回路

文章没有把 observability 写成后台指标，而是写成产品迭代方式：改 prompt、改工具集、跑查询、立刻看 trace。

  • Prompt 与工具迭代：从 trace 里看 agent 做了什么、为什么这样做。
  • 成本跟踪：按节点拆 token 成本，定位昂贵步骤。
  • 缓存命中分析：动态技能和工具加载会影响 prompt caching，trace 能显示哪里失效。
  • 错误诊断：在问题变成用户可见故障前发现 tool call 失败和异常模型行为。

最终信号：B2B 企业销售场景先跑通

Moda 已在需要快速创建精致、品牌一致 pitch deck 的 B2B 公司中看到早期 product-market fit。接下来文章提到三件事：接入已经准备好的 memory primitives、完成 Design Agent 到 Deep Agents 的迁移、扩展品牌上下文以支持多团队和多品牌企业客户。
