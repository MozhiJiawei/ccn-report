Two different types of agent authorization

Agent 授权要区分代表用户行动，还是使用 agent 自己的固定凭证。

核心观点：Why: agent 调用企业工具时，最危险的模糊地带是它以谁的身份取数和行动。What: 文章把授权拆成两类：Assistant 代表最终用户，Claw 使用 agent 自己的固定凭证。How: LangSmith Fleet 用渠道身份映射、共享权限和 human-in-the-loop guardrails，把这两类 agent 放进不同使用场景。

文章的主张集中在这三点

这些子观点都服务于首屏结论，帮助读者快速抓住文章的判断框架。

01

Assistant 适合个人权限边界

on-behalf-of 模式让 onboarding agent 只能看到 Alice 自己能访问的 Rippling 和 Notion 信息。

02

Claw 适合团队共享 agent

固定凭证可以来自专用账号，适合 email agent、product agent 或团队 bot，但敏感动作需要审批。

03

授权类型会影响 memory 设计

文章指出未来需要更细的 memory permissions，避免一个用户的敏感记忆在另一个人的对话里被复用。
