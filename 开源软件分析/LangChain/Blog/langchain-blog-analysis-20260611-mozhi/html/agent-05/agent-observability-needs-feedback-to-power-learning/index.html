Agent observability needs feedback to power learning

Harrison Chase · May 5, 2026 · 8 min · 原文链接

Why: 只看 trace 能定位 agent 做了什么，却无法判断结果是否有用。What: 文章把 agent observability 的核心从调试扩展为学习：trace 加 feedback 才能形成改进信号。How: 团队把用户反馈、行为信号、LLM-as-judge 和规则检查贴到同一条 run、trace 或 thread 上，再用这些信号改模型、harness、context、评测集和规则。

Trace

记录模型调用、工具调用、上下文、输出、错误和中间状态。

Feedback

说明一次行为是成功、失败、低效、危险，还是被用户接受。

Learning

把生产行为转成数据集、在线评测、规则、告警和人工复核队列。

Trace 让行为可见，feedback 让含义可见

二者绑定到同一次运行后，观测数据才会进入学习闭环。

Traces

行为可见：agent 看到了什么、调用了什么、返回了什么。

Feedback

意义可见：哪些轨迹代表成功、失败或值得复核。

Changes

改 prompt、工具、memory、routing、eval dataset 或模型行为。

←

Learning

识别反复出现的模式，把真实轨迹变成可复用的改进材料。

学习不是单点训练，而是模型、harness、context 一起变好

模型层

当 trace 显示模型反复误分类、选错工具或违反策略，样例可以进入 SFT 或 RL 等模型更新路径。

Harness 层

prompt、工具 schema、权限检查、控制流、重试和 guardrail 都属于模型外的脚手架，trace 能暴露这些结构是否误导了 agent。

Context 层

当模型基于缺失或错误上下文做出合理但无效的判断，改进方向是检索、记忆、压缩或丢弃策略。

Feedback 的价值在于贴到具体轨迹上，而不是散落在别处

文章强调，trace 本身只回答“发生了什么”。要判断 40 步是否过长、答案是否被拒绝、工具参数是否微妙错误，就需要把反馈和具体 run、trace 或 thread 关联起来。这样团队才能筛出好坏轨迹、比较变化前后行为，并把真实失败转为评测集。

直接用户反馈

thumbs up/down、评分、文字修正，清晰但通常稀疏。

间接行为信号

代码是否被接受、ticket 是否重开、答案是否被复制或重复提问，噪声更大但数量更多。

LLM-as-judge

用模型按有用性、策略遵循或可疑轨迹打分，可作为生产 trace 上的在线 evaluator。

确定性规则

regex 和规则能低成本捕捉已知失败模式，例如危险命令、缺少引用或用户挫败信号。

面向学习的 observability 平台有三件事要合在一起

Store traces

保存完整轨迹：模型调用、工具调用、输入输出、metadata、timing、错误和中间状态。文章提到 LangSmith 可接入 30+ frameworks，也支持 OpenTelemetry-compatible 应用的 tracing。

Store feedback

反馈直接关联到它评价的 run、trace 或 thread，用来过滤轨迹、构建数据集、比较好坏行为，并观察改动是否改善关键指标。

Generate feedback

系统通过规则、evaluator、sampling、annotation queue、alerts 和 backfill 自动生成信号。文章指出 LangSmith 支持 automation rules 和 online evaluations。
