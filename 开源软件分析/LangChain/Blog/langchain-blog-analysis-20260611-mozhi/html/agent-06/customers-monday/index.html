案例 · February 18, 2026 · 8 min

Whymonday Service 的 ReAct service agents 会在多步推理和工具调用中级联出错，质量不能等 Alpha 用户发现。
What团队把 evaluations 作为 Day 0 要求，形成 offline safety net 与 online monitor 两层体系，并把反馈循环从 162 秒压到 18.6 秒，快 8.7 倍。
Howoffline 层用 LangSmith + Vitest 跑 curated datasets、deterministic checks 和 LLM-as-judge；online 层用 Multi-Turn Evaluators 评估生产会话，并把 judges 作为 TypeScript 代码通过 CI/CD 同步到 LangSmith。

两层 eval 架构覆盖发布前和生产中

Offline Evaluations 像 safety net：用 golden datasets 检查 runtime、schema、state persistence、tool calls、correctness、grounding、guardrails 和 trajectory。Online Evaluations 像 monitor：在真实 production traces 上评估多轮对话的满意度、语气和目标达成。

速度来自 CPU 并行和 LLM I/O 并发

原先串行 eval 让 fail-fix-pass 循环变慢。团队把 dataset shard 分到 Vitest forks，并在每个 test file 中用并发跑高延迟 LLM evaluations，使 20 个 sanitized IT tickets 从 162.35s 降到 18.60s。

Judges 被当作生产代码管理

monday 把 Multi-Turn Evaluator prompts 写成 TypeScript 对象，使用 IDE 和 MCP 拉取上下文，在合并 PR 后通过 `yarn eval deploy` 同步 prompt registry、reconcile rules，并 prune 已不存在的 production evaluators。

案例的核心不是单个分数，而是评估基础设施化

文章把成熟方向称作类似 Terraform modules 的 Evaluations as Infrastructure：LangSmith 提供 eval 基础设施，团队保留 version control、peer review 和 CI/CD 的工程纪律。
