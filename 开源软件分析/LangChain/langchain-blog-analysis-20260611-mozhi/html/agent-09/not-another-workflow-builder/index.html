Not Another Workflow Builder

Why: 传统 workflow builder 容易把 agent 设计成静态流程图，但真实 agent 往往需要状态、工具、分支和迭代调试。
What: LangChain 认为自己的构建体验不是再做一个拖拽流程工具，而是把可视化和代码式 agent 工程结合起来。
How: 通过让开发者保留 LangGraph/LangChain 的代码表达力，同时提供可观察、可调试、可协作的产品界面来管理复杂性。

5-second takeaway

LangChain 认为自己的构建体验不是再做一个拖拽流程工具，而是把可视化和代码式 agent 工程结合起来。

问题先于方案

传统 workflow builder 容易把 agent 设计成静态流程图，但真实 agent 往往需要状态、工具、分支和迭代调试。

核心变化只有一个

LangChain 认为自己的构建体验不是再做一个拖拽流程工具，而是把可视化和代码式 agent 工程结合起来。

路径落在具体机制上

通过让开发者保留 LangGraph/LangChain 的代码表达力，同时提供可观察、可调试、可协作的产品界面来管理复杂性。

静态流程图不是 agent 工程的全部答案

文章指出 agent 的价值来自工具使用、状态、上下文和动态决策，纯拖拽流程很容易掩盖这些复杂性。

代码表达力仍然是复杂 agent 的底座

LangChain 倾向让核心逻辑留在开发者可测试、可版本化的代码中，而不是完全藏进画布配置。

界面价值在于理解和改进运行行为

可视化能力更适合承载 traces、状态、评测和协作，而不是把所有工程决策压平成流程块。
