问题先于方案

核心变化只有一个

LangChain 用 DeepAgents 0.2 把这个方向继续产品化，核心新增是可插拔 Backend。

路径落在具体机制上

通过 planning tool、filesystem、subagents、详细 prompt，再叠加 State / Store / Local FS / 自定义 backend，Deep Agents 成为建立在 LangChain agent 抽象和 LangGraph runtime 之上的 agent harness。

Deep Agents 的价值在于把长流程所需支架预装好

文章把 Deep Agents 描述为面向复杂工作的默认 harness：不只调用模型和工具，还把计划、文件、子 agent 与提示词组织为一个可复用结构。

0.2 版把文件系统从实现细节变成可替换后端

可插拔 backend 让同一 agent 逻辑可以落到 LangGraph State、Store、本地文件系统或团队自己的存储上，减少从原型迁移到生产时的重写。

它补齐的是 runtime 之外的工作习惯

LangGraph 负责持久执行和状态图，LangChain 负责 agent 抽象；Deep Agents 把长上下文、工具结果和子流程协作变成默认工作方式。
