核心判断How we built Agent Builder's memory system

技术长文 · February 21, 2026 · 9 min

WhyAgent Builder 面向重复执行同类任务的自定义 agent，没有记忆会让用户在不同会话里反复校正同一件事。
WhatLangChain 把记忆实现为 agent 可读写的文件形态，并映射到 COALA 的 procedural、semantic、episodic 记忆分类。
How底层用 Postgres 存储并暴露成虚拟文件系统，AGENTS.md、skills、tools.json 和知识文件分别承载指令、专门知识与工具配置，所有记忆更新通过人工确认降低注入风险。

文件形态让无代码 agent 仍然可组合

文章的关键设计是把 memory 变成 markdown 和 json 文件，而不是专有 DSL。AGENTS.md 定义核心指令，skills 提供任务专用上下文，tools.json 约束 MCP 工具子集，其他知识文件保存可复用事实。

虚拟文件系统把模型习惯和基础设施效率折中起来

LLM 擅长读写文件，但生产存储更适合数据库。Agent Builder 因此把文件存在 Postgres，再以文件系统形态交给 Deep Agents；同一抽象也可替换为 S3、MySQL 等后端。

难点不在存储，而在记忆行为控制

团队发现最难的是 prompting：什么时候记、什么时候不记、写入 AGENTS.md 还是 skills、如何保持技能文件格式。为此他们加入 schema validation，把错误回传给 LLM，并让用户批准记忆修改。

未来补齐 episodic 与后台整理

当前系统主要覆盖 procedural 和 semantic memory。后续方向包括把历史会话暴露成文件、后台周期性反思和泛化、显式 `/remember`、semantic search，以及 user-level / org-level memory。
