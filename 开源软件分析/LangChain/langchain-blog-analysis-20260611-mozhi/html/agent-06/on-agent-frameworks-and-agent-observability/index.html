薄观点文 / 架构观点 · February 12, 2026 · 5 min

Whyagent frameworks 常被质疑会被模型进步淘汰，但团队仍需要更快构建、更少重复代码和可生产化路径。
WhatLangChain 的立场是 frameworks 仍有用，但要随模型演进；同时 LangSmith observability 与 evals 不绑定 LangChain 或 LangGraph。
HowLangChain 把 framework 演进分为 chaining、LangGraph runtime、Deep Agents harness 三代，并让 LangSmith 通过多框架集成和 OpenTelemetry tracing 支持任意 agent。

Frameworks 的价值从抽象链路转向编码最佳实践

文章承认早期 langchain 曾被批评过于 opinionated，但强调好框架能减少 boilerplate、编码 best practices、提高质量、增强团队可读性，并提供更清晰的生产路径。

三代 agent 形态对应三层工具

第一代是 chaining 和 RAG，第二代是 LangGraph 的 durable、stateful orchestration/runtime，第三代是 Deep Agents harness，支持 long-horizon planning、tool-calling loop、filesystem context offloading 和 subagent orchestration。

LangSmith 独立于 OSS 是产品立场

LangSmith 从一开始就假设不会只有一个 agent framework。它集成 AutoGen、Claude Agent SDK、CrewAI、Mastra、OpenAI Agents、PydanticAI、Vercel AI SDK 等，并支持 OpenTelemetry ingestion。

Agent engineering 让 build、debug、test、monitor 汇合

文章最后强调 traces 是 agent 行为的事实记录。agent app logic 不只在代码里，也在 traces 里；因此 observability、evals 和 monitoring 是构建过程的一部分。
