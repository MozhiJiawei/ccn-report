WhyExa 从搜索 API 和 answers endpoint 走向深度研究 API，需要能自主探索网页并稳定输出结构化结果的生产级 agent。

WhatExa 用 LangGraph 构建 Planner、Tasks、Observer 多 agent 架构，每天处理数百个研究查询，并在约 15 秒到 3 分钟内返回结构化结果。

一句话带走

Exa 用 LangGraph 构建 Planner、Tasks、Observer 多 agent 架构，每天处理数百个研究查询，并在约 15 秒到 3 分钟内返回结构化结果。

关键机制

Planner 动态生成并行研究单元，Tasks 使用 Exa API 工具按 JSON schema 输出，Observer 保留全局上下文；LangSmith 追踪 token、缓存和 reasoning token 用量以支撑定价与成本控制。

阅读定位

这是一篇case study，重点看它如何把具体场景、产品能力或架构取舍连成一个可执行判断。

复杂搜索让框架从可选变成关键

Exa 原 answers endpoint 不依赖框架；当产品演进到长运行、多单元 deep research 时，团队重新评估并选择 LangGraph。

上下文被刻意分层而不是全量共享

Observer 看全局，单个 task 只接收其他研究单元的清理后结果；snippet 优先、必要时再抓全文，降低 token 成本。

API 消费决定了结构化输出优先

每个研究单元都带 required output format，并用 function calling 生成 JSON，保证下游客户拿到可解析结果。
