模型换了，Agent harness 也要跟着调。

Why

Deep Agents 过去用一套通用 prompts、tools 和 middleware 覆盖所有大模型，但不同模型的提示指南和工具约定差异很大。

What

LangChain 引入 model-specific harness profiles，并内置 OpenAI、Anthropic、Google profiles；在 tau2-bench 子集上，相比默认 harness 提升 10 到 20 个百分点。

How

Profile 作为声明式覆盖层，按模型调整 system prompt、工具包含与命名、middleware、subagent 配置和 skills，同时保持 create_deep_agent 调用方式不变。

Model fit

每个模型家族吃到的优化点不同，通用 harness 很难同时命中。

文章把 Codex 和 Claude prompting guides 作为变更来源：Codex 更依赖工具实现与命名约定，Claude/Opus 更依赖工具结果反思、主动观察文件和测试状态等 prompt 规则。

Codex: 工具名对齐

把 deepagents 默认的 edit_file 覆盖为推荐的 apply_patch，并把 execute 工具别名为 shell_command。

Codex: 调用节奏

prompt 强调工具调用前先判定所需文件与资源，并把独立读取、搜索等操作并行化。

Opus: 观察优先

prompt 强调用工具直接读取文件、运行测试、搜索代码，再基于真实状态继续规划。

原文结论：per-model harness customization 是一个有用 primitive，可帮助 builders 管理、版本化并测试不同 agent 配置。

Mechanism

profile 是覆盖层，不是新的调用入口。

开发者可以为 model 或 provider 注册 profile，也可以从 YAML 载入已有 profile；当模型切换时，create_deep_agent 自动适配。内置 profile 覆盖 OpenAI、Anthropic 和 Google，同时支持再覆盖、叠加或作为 plugin 分发。

Takeaway

Deep Agents 的方向是让模型差异进入配置层，而不是散落在业务代码里。

这篇文章不是单纯宣布一个配置文件格式，而是在强调 agent harness 本身会影响模型表现。profiles 把这些差异集中到可管理、可复用、可测试的层里，让同一套 Deep Agents 调用可以贴近不同模型的最佳默认值。
