Deep Agents v0.5

Why：长时间研究、代码分析和多步骤操作会阻塞 supervisor agent，单线程等待让 Deep Agents 难以处理更重的工作。 What：Deep Agents v0.5 发布 async subagents，并扩展虚拟文件系统的多模态读取能力。 How：supervisor 可以启动远程 agent 后拿到 运行 ID 继续工作；远程端通过 Agent Protocol 的 threads/runs 模型承接状态，read_file 则自动按扩展名传递 PDF、音频、视频等 MIME content block。

Why

长时间研究、代码分析和多步骤操作会阻塞 supervisor agent，单线程等待让 Deep Agents 难以处理更重的工作。

What

Deep Agents v0.5 发布 async subagents，并扩展虚拟文件系统的多模态读取能力。

How

supervisor 可以启动远程 agent 后拿到 运行 ID 继续工作；远程端通过 Agent Protocol 的 threads/runs 模型承接状态，read_file 则自动按扩展名传递 PDF、音频、视频等 MIME content block。

一句话带走

Deep Agents v0.5 把 subagent 从同步工具变成后台工作。长时间工作不再卡住 supervisor，远程 agent 通过 Agent Protocol 保持 thread/run 状态；同一版还把虚拟文件系统从图片扩展到 PDF、音频和视频。

文章真正强调的三件事

后台 subagent 解除等待

async subagents 返回 运行 ID，supervisor 可以继续对话或启动更多工作，再按需取回结果。

协议选择服务于工作模型

Agent Protocol 的 thread 和 run 正好对应“保留上下文、启动工作、稍后检查”的交互。

多模态读取保持同一接口

agent 仍使用 read_file；文件类型从扩展名检测，并按模型支持传入原生 content block。

支撑观点的机制

这次版本的主线是并发而不是新包装

inline subagents 适合短时间工作，但深度研究或大规模代码分析通常要跑几分钟。v0.5 让 supervisor 不再把全部控制权交给一个阻塞调用。

Agent Protocol 让远程 subagent 有状态

文章比较 ACP 和 A2A 后选择 Agent Protocol，核心理由是它已有 HTTP、thread/run 和 LangGraph Platform 基础，能快速贴合 async subagent 的状态模型。

多模态支持扩展了文件系统的表达力

Deep Agents 过去能读图片，现在能用相同 read_file 工具读取 PDF、音频、视频等文件；是否可用取决于底层模型 profile。
