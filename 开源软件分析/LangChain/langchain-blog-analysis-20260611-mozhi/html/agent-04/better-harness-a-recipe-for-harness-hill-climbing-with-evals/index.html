Why

agent 质量往往不是只改模型就能提升，真正可更新的是 harness；但 autonomous harness improvement 需要可靠学习信号。

What

Better-Harness 把 evals 当作 harness engineering 的训练数据，用数据 sourcing、实验设计、优化、review & acceptance 形成 hill-climbing loop。

How

系统从真实失败、人工 curated evals 和 traces 中构造信号，约束过拟合，保存长期 traces，并让 agent 提议 harness changes 后进入人工 review。

一句话带走

Better-Harness 的观点很直接：如果 agent 是 compound system，evals 就是 harness engineering 的训练数据。系统用 eval 信号爬坡，自动提出 prompt、tool、memory 或 routing 层改动，再用 review 和防过拟合设计控制泛化。

文章真正强调的三件事

evals 是 harness 的梯度信号

每个 eval case 都表达期望行为，例如是否采取正确动作、是否产出正确结构。

数据质量决定爬坡方向

文章强调 eval sourcing 和 curation，避免 agent 只在一套脆弱测试上刷分。

自动优化后仍要人工接收

Better-Harness 包含 review & acceptance，把自动发现的 harness 变化放进可审查流程。

支撑观点的机制

文章把机器学习类比迁移到 agent harness

传统 ML 用训练数据更新权重；agent engineering 则用 evals 更新 system prompt、tool description、memory、routing 和 orchestration。

Better-Harness 不只是一条优化循环

它还包含 eval 来源、实验设计、trace 存储、过拟合防护和人工 sanity check，这些决定改动是否能泛化。

例子集中在 harness 层变化

文章提到的 changes 不是换一个模型这么简单，而是修改工具说明、上下文策略、agent 指令和可执行流程。
