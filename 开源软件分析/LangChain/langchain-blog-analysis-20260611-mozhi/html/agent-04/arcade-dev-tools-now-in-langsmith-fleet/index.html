Arcade.dev tools now in LangSmith Fleet

Why：Fleet 里的 agent 要跨 Salesforce、Notion、Slack 等工具工作，真正的瓶颈不是多接几个 API，而是连接、授权和治理会迅速膨胀。 What：LangSmith Fleet 接入 Arcade.dev，把 7,500+ agent-optimized tools 放到一个安全 MCP gateway 后面，并支持 60+ 预配置模板。 How：Arcade 提供单一 gateway、面向 agent 缩窄过的工具描述，以及 per-user/session-scoped authorization；Fleet 决定凭据以用户身份还是共享身份流入 Arcade。

Why

Fleet 里的 agent 要跨 Salesforce、Notion、Slack 等工具工作，真正的瓶颈不是多接几个 API，而是连接、授权和治理会迅速膨胀。

What

LangSmith Fleet 接入 Arcade.dev，把 7,500+ agent-optimized tools 放到一个安全 MCP gateway 后面，并支持 60+ 预配置模板。

How

Arcade 提供单一 gateway、面向 agent 缩窄过的工具描述，以及 per-user/session-scoped authorization；Fleet 决定凭据以用户身份还是共享身份流入 Arcade。

一句话带走

工具越多，agent 越需要统一入口和权限边界。Arcade.dev 进入 LangSmith Fleet 后，重点不是“又多一批 MCP server”，而是把 7,500+ agent-optimized tools 放到可治理的 gateway 后面。Fleet 负责 agent 与凭据流，Arcade 负责工具选择、授权和一致化调用。

文章真正强调的三件事

Gateway 降低集成税

每个工具单独接入都会带来 auth flow、API 差异和维护成本；Arcade MCP Gateway 给 Fleet agent 一个统一入口。

工具不是 API 包装

文章强调 Arcade 工具面向 agent 重新设计：缩小能力面、统一结构、让描述更适合模型选择与调用。

权限跟着使用者走

Assistants 使用用户自己的凭据，Claws 使用共享凭据；Arcade 在运行时执行最小权限和 session-scoped authorization。

支撑观点的机制

Fleet 的扩展点从模型转向工具治理

LangSmith Fleet 让团队创建和共享日常工作 agent。文章把外部工具连接看作和 LLM gateway 类似的集中治理问题，只是工具侧的 auth、schema 和维护成本更高。

Arcade 把 MCP gateway 做成 agent 友好的工具层

Arcade 不只是把 REST API 包成 MCP。它把工具面缩窄到 agent 常用动作，保持结构一致，并把描述写成模型更容易选择的意图。

授权模式决定 agent 能代表谁行动

当 agent 代表个人办事时，Fleet 把用户凭据传给 Arcade；当 agent 代表团队或服务办事时，Claws 使用固定共享凭据。这个区分让工具访问更贴近组织权限模型。
