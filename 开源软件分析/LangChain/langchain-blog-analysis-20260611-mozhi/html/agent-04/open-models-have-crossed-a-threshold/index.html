Open Models have crossed a threshold

Why：agent 工作如果总用最强闭源模型，成本和延迟会成为规模化瓶颈；开源/开放权重模型是否能承担核心 agent 行为，需要 eval 证据。 What：LangChain 的 Deep Agents harness evals 显示，GLM-5 和 MiniMax M2.7 等 open models 在文件操作、工具调用、指令跟随等核心行为上已接近闭源 frontier models，并有成本/延迟优势。 How：文章用 harness evaluations 比较模型在实际 agent 行为上的表现，并建议按 cost、latency、task performance 组合使用 open 与 closed models。

Why

agent 工作如果总用最强闭源模型，成本和延迟会成为规模化瓶颈；开源/开放权重模型是否能承担核心 agent 行为，需要 eval 证据。

What

LangChain 的 Deep Agents harness evals 显示，GLM-5 和 MiniMax M2.7 等 open models 在文件操作、工具调用、指令跟随等核心行为上已接近闭源 frontier models，并有成本/延迟优势。

How

文章用 harness evaluations 比较模型在实际 agent 行为上的表现，并建议按 cost、latency、task performance 组合使用 open 与 closed models。

一句话带走

开放模型已经进入可用于 agent harness 的阶段。文章不是宣称它们全面替代闭源 frontier models，而是用 Deep Agents evals 指出：在文件操作、工具调用和指令跟随等核心行为上，GLM-5、MiniMax M2.7 这类模型能用更低成本与延迟承担一部分生产负载。

文章真正强调的三件事

阈值来自 agent 行为评测

文章关注的不是通用榜单，而是 Deep Agents harness 中的文件、工具和指令跟随能力。

成本和延迟改变模型选择

最高 reasoning level 的 frontier model 适合最难环节，但 8-10x 成本和延迟让它不适合作为所有步骤默认值。

模型组合比单一赢家更现实

开放模型可与闭源模型并用，让 agent 按工作难度和运行预算选择执行层。

支撑观点的机制

模型选择从“最强”转向“足够强且可规模化”

agent 系统往往包含大量工具调用、文件读取和中间步骤。每个环节都用最贵模型，会把成本与等待时间放大。

Deep Agents evals 给出实际行为信号

文章把 GLM-5、MiniMax M2.7 等模型放进 harness evals，关注它们是否能可靠操作文件、调用工具、跟随指令，而不是只看开放 benchmark。

开放模型的价值在混合部署

当工作可以被较低成本模型稳定完成时，闭源 frontier model 可以留给高难度推理环节。这个分层是文章真正的生产化主张。
