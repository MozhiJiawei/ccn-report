LangChain Ecosystem Map

LangChain 不是一个库，而是一组 agent 工程层

理解 LangChain 生态，最好不要从“哪个包怎么调用”开始，而是从层次看：底层是模型、工具、数据连接；中间是 agent 编排和运行时；上层是更有主见的 agent harness；旁边还有观测、评测、部署和业务用户入口。

5 秒结论：LangChain 负责“搭积木”，LangGraph 负责“让复杂 agent 按状态可靠运行”，Deep Agents 负责“把长任务 agent 的常见结构预装好”，LangSmith 负责“看见、评测、部署和持续改进”。
大颗粒组件地图
业务入口

Agent Builder / Fleet：给非工程或平台团队用自然语言、工具、memory 和审批来创建可复用 agent。

Agent Harness

Deep Agents：预装 planning、filesystem/context、subagents、multi-agent orchestration，面向研究、编码、长流程任务。

编排运行时

LangGraph：低层图编排与 runtime，处理 state、checkpoint、streaming、human-in-the-loop、长运行 agent。

构建积木

LangChain：模型、messages、tools、retrievers、prompts、middleware、integrations 等基础抽象。

工程平台

LangSmith：tracing、observability、evaluation、deployment、monitoring、Engine、Gateway、Context Hub 等工程化能力。

每个组件到底干嘛

下面按“你什么时候会用它”来理解，不按仓库或套餐名理解。实际项目里常常是多层一起用：LangChain 提供积木，LangGraph 提供运行骨架，Deep Agents 提供默认 agent 形态，LangSmith 提供工程闭环。

基础框架 / building blocks

LangChain

用来快速连接模型、工具、数据源和应用逻辑。它更像 agent / LLM app 的通用零件箱。

  • 模型与 provider 适配
  • messages、tools、prompts、retrievers
  • 适合 RAG、工具调用、简单 agent、应用集成
编排框架 / runtime

LangGraph

用来写状态ful、长运行、可恢复、可观察的 agent workflow。它更低层，给你控制权。

  • graph state、节点、边和条件路由
  • checkpoint、interrupt、resume、streaming
  • 适合复杂流程、多 agent、人工审批、生产 runtime
高层 agent harness

Deep Agents

用来少写底层图逻辑，直接得到一个适合复杂任务的 agent 模板。它内置了一套对长任务有用的结构。

  • planning、subagents、filesystem/context
  • 基于 LangGraph runtime，使用 LangChain 积木
  • 适合研究、编码、尽调、数据分析等长任务
观测 / 评测 / 部署平台

LangSmith

用来把 agent 从 demo 拉进工程循环：看 trace、做 eval、监控线上行为、部署和持续改进。

  • traces、datasets、experiments、evaluators
  • deployment、monitoring、Engine、Insights
  • 可接 LangChain/LangGraph，也可框架无关接入
业务用户入口

Agent Builder / Fleet

用来自然语言创建和管理 agent，让业务用户或平台团队把工具、memory、skills 和审批编进日常工作。

  • no-code / low-code agent creation
  • memory、MCP tools、共享、权限、审批
  • 底层依赖 Deep Agents / LangSmith 能力
平台服务

Sandboxes / Context Hub / Gateway

这些不是“再一个 agent 框架”，而是生产 agent 的配套设施：隔离执行、上下文版本管理、模型访问治理。

  • Sandboxes：隔离代码与文件执行
  • Context Hub：管理 AGENTS.md、skills、policy 等上下文文件
  • LLM Gateway：集中模型路由、成本与策略控制

它们之间是什么关系

层一句话定位典型问题不是用来干嘛的
LangChain连接模型、工具和数据的基础框架。“我怎么把模型、检索、工具调用接起来？”不负责替你管理复杂长流程 runtime。
LangGraph状态机 / 图式 agent runtime。“我的 agent 有状态、会分支、要恢复、要人工介入，怎么可靠跑？”不是最高层的业务 agent 模板，需要你自己设计 graph。
Deep Agents预置长任务结构的 agent harness。“我想快速做一个会规划、会拆子任务、会管理上下文的复杂 agent。”不是无代码产品；仍是开发者构建框架。
LangSmithagent 工程平台。“我怎么知道 agent 为什么失败、如何评测、如何部署、如何持续改？”不是替代 LangChain/LangGraph 的编排框架。
Agent Builder / Fleet面向业务/组织使用的 agent 创建与管理入口。“非工程团队怎么创建、共享、治理可用 agent？”不是底层 runtime；它封装上面的能力。
1. 简单 LLM App

优先用 LangChain / LlamaIndex / Haystack 这类积木和 RAG 框架。

2. 有状态流程

进入 LangGraph / OpenAI Agents SDK / LlamaIndex Workflows / AutoGen。

3. 复杂长任务

考虑 Deep Agents / CrewAI crews / AutoGen 多 agent patterns。

4. 生产质量闭环

接 LangSmith / Langfuse / Phoenix / Weave 做 trace、eval、monitor。

5. 组织化使用

用 Agent Builder/Fleet 或企业内部平台管理工具、权限、memory 和审批。

业界对标：不要一对一，按层对标

LangChain 生态是“框架 + runtime + harness + 工程平台”的组合，很多竞品只覆盖其中一层。因此更准确的对标方式是按层看。

LangChain 组件相近定位常见对标/替代怎么区分
LangChain LLM app / agent building blocks LlamaIndex、Haystack、Semantic Kernel、Vercel AI SDK LangChain 更通用；LlamaIndex/Haystack 在 RAG、数据连接、pipeline 上很强；Vercel AI SDK 偏前端/全栈 AI UI。
LangGraph 状态ful agent orchestration/runtime OpenAI Agents SDK、Microsoft AutoGen、LlamaIndex Workflows、CrewAI Flows LangGraph 更像可控状态图和 runtime；OpenAI Agents SDK 更贴 OpenAI Responses/Agents 栈；AutoGen 偏 event-driven/multi-agent；CrewAI 偏角色协作和流程。
Deep Agents opinionated long-running agent harness CrewAI Crews、AutoGen teams、OpenAI Agents SDK handoffs + sessions、自研 coding/research agent harness Deep Agents 重点是 planning、context/filesystem、subagents 和 LangGraph runtime；CrewAI 更强调 crew/role/task；OpenAI Agents SDK 更轻量集成 handoffs、guardrails、sessions。
LangSmith observability / eval / deployment / improvement platform Langfuse、Arize Phoenix、W&B Weave、Braintrust、Humanloop、Galileo LangSmith 与 LangChain/LangGraph 集成最深；Langfuse 开源、自托管和 prompt/eval/tracing 组合强；Phoenix 偏 OpenTelemetry/OpenInference trace 与 eval；Weave 与 W&B 实验生态强。
Agent Builder / Fleet no-code / managed agent workspace CrewAI Enterprise、OpenAI Agent Builder/ChatKit 类能力、内部 agent platform、Zapier/Make 的 AI automation 对标的是“让组织里更多人创建和运行 agent”，不是底层框架。关键差异通常在工具接入、权限、审批、memory 和可观测闭环。
读 LangChain 文章时可以用这个判断：如果文章讲 tools/prompt/retriever，多半是 LangChain 层；讲 state/checkpoint/streaming/human-in-the-loop，多半是 LangGraph；讲 planning/filesystem/subagents，多半是 Deep Agents；讲 traces/evals/monitoring/deployment，多半是 LangSmith。

一个项目怎么选

你现在的问题优先看为什么
我要做 RAG、工具调用、简单 assistantLangChain 或 LlamaIndex/Haystack先解决模型、数据、工具连接，不要一上来上复杂 runtime。
agent 会跑很多步，要恢复、审批、分支和状态LangGraph你需要的是 stateful runtime，而不是更长 prompt。
我要做 research/coding/分析类长任务 agentDeep Agents + LangSmith长任务通常需要 planning、文件化上下文、subagents 和 trace/eval 闭环。
我已经有 agent，但不知道为什么失败LangSmith / Langfuse / Phoenix / Weave先看 trace、建 eval、找失败模式，再决定改 prompt、工具、上下文还是 runtime。
我想让业务同学自己创建 agentAgent Builder / Fleet 或自建平台问题变成工具权限、memory、审批、共享和组织治理。
