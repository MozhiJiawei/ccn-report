Legal-agent verifiers become scalable when cost is treated as a design axis.

这篇文章的核心不是换一个 judge 模型，而是把“如何验证法律 agent 的答案”拆成可调系统：减少调用次数、使用更便宜的模型，并从 trace 中校准 false pass。

Why

法律工作跨文档、标准细、误放行代价高；LAB 里很多工作项含 50+ 条 criteria，逐条调用 frontier verifier 会让评测和 RL 后训练成本迅速放大。

What

Harvey 与 LangChain Labs 的实验显示，batch verifier 和 open model verifier 能把成本降一个数量级到三个数量级，但要接受不同程度的 label drift。

How

文章以 Opus 4.7 per-criterion 为参照，在 40 个 LAB 公开工作项、2,348 条 criteria 上比较模型与评分方式，再用 trace 驱动提示词调优来压低 false pass。

瓶颈来自“每条 criteria 都要一次判断”。

LAB 的验证方式接近人工审阅：一个输出要逐条对照 rubric criteria，所有 criteria 通过才算完成。这个设计让结果更可审计，也让调用次数随 criteria 数量线性增长。

50+criteria per work item

原文指出很多 LAB 工作项有超过 50 条独立 criteria；per-criterion verifier 会为每一条生成一次 pass/fail verdict。

2,348criteria in the run

实验用 Kimi K2.6 生成 40 个公开 LAB 工作项的 agent 输出，再让不同 verifier 为同一批 criteria 打标签。

更少 token 的办法，是把逐条判断改成整组判断。

Batch scoring 用一次调用处理整份 rubric，节省重复输入 token；代价是 judge 要在更大的上下文里同时跟踪多条 criteria，因此文章观察到 batch 的 match rate 通常低于 per-criterion。

1 callbatch scoring

Batch 不是改变 rubric，而是把所有 match criteria 放入同一次判断，让 judge 同时返回多条 verdict。

lower costhigher drift risk

文章的取舍很清楚：batch 省钱省时，但在同模型对比中 label match rate 更低，适合接受噪声换规模的场景。

更便宜 token 的关键，是找接近 frontier 标签的 open verifier。

研究以 Opus 4.7 per-criterion 标签为参考，比较 GPT-5.5、Sonnet 4.6、DeepSeek v4 Flash、Claude Haiku 4.5。结论不是“最便宜就最好”，而是要同时看 cost、label drift 和 false pass。

DeepSeek 是强近似。

原文称 DeepSeek 在逐条和 batch 两种方式下都能较好近似 Opus，同时成本可低三个数量级。

Haiku 的失败形态不适合法律验证。

Haiku 成本更低，但 false-pass 率高：per-criterion 48.4%，batch 34.7%。在法律场景里，错放行比错拦截更危险。

frontier 模型也会互相分歧。

GPT-5.5 与 Opus 的 match rate 为 95.7%；文章据此提醒，追求 100% 一致并不现实。

后训练会放大 verifier 成本，便宜 reward signal 直接影响迭代速度。

LLM-as-judge 不只用于离线评测，也会把 rubric 转成 reward signal。RL 训练中一次工作会产生多次 rollout，因此 verifier 花费会被进一步放大。

$18kOpus per-criterion

原文的 3,200 rollout 估算中，Opus per-criterion verifier 成本约 $18k。

$18DeepSeek batch

同一估算下 DeepSeek batch 约 $18，文章称约比 Opus 便宜 1,000x。

trace 还能把 verifier 调成更谨慎的法律审阅者。

文章最后展示了一个小但重要的杠杆：固定模型和评分方式后，分析 DeepSeek 相对 Opus 的分歧 trace，再改写提示词，让 verifier 将 criteria 拆成 checklist，并在信息不完全清楚时更谨慎。

1. 找分歧比较 DeepSeek 与 Opus 的标签差异，聚焦 false pass。
2. 改行为让 verifier 显式拆解 criteria 的每个组成部分。
3. 降误放DeepSeek false-pass 从 10.7% 到 9.5% per-criterion，从 15.6% 到 14.2% batch。
