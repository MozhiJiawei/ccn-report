Give your agent its own computer

Why

会运行代码、安装依赖、处理文件和保持长会话的 agent，不能直接共享开发者电脑或普通容器边界。

What

LangSmith Sandboxes 给每个 agent 一个硬件虚拟化 microVM，兼具快速启动和有状态机器能力。

How

开发者用 SDK 创建 sandbox 并运行命令，依靠 snapshots/forks、blueprints、service URLs、Auth Proxy 和默认私有访问来支撑生产级执行。

agent 需要工作地点，不只是 token stream。

数据分析、CI、研究、内容流水线和 RL/eval harness 都要拉文件、跑脚本、装依赖、启动服务或并行环境；这类工作需要可执行、有状态的环境。

普通容器不是针对不受信任 agent 代码的隔离答案。

文章指出 agent 运行的代码可能来自模型、用户 prompt、克隆仓库或包依赖；容器共享宿主内核，不适合作为 untrusted model-generated code 的最终隔离边界。

microVM 同时提供隔离和长会话工作能力。

sandbox 有自己的 kernel、filesystem、shell、package manager、network access、code execution 和 persistent state；结束后环境消失，不触碰生产基础设施或其他 sandbox。

GA primitive 让 agent workflow 更像生产系统。

snapshot/fork 支持分支试错，blueprint 预热环境，service URL 打开 agent 启动的本地服务，Auth Proxy 让凭据停留在 runtime 外部。
