LangGraph 的容错重点，是把失败恢复放进节点执行模型

Why：生产 agent 会遇到网络故障、工具错误、LLM 限流和长时间卡住的问题；一次长时间运行半路失败，重头再来不可持续。What：文章把 LangGraph 的容错归纳为三件事：RetryPolicy 处理瞬时错误，TimeoutPolicy 防止节点无限挂起，error_handler 在重试耗尽后进入清理、告警、降级或补偿路径。How：这些策略直接挂在 StateGraph.add_node 的节点上，由运行时在 checkpoint 中原子记录失败并调度处理器，使 SAGA 这类多步骤副作用流程能续跑到正确的补偿步骤。

Why

生产流程里的 1% 瞬时失败会在几十个步骤中放大，尤其当 agent 已经调用外部系统、付款或订票时。

What

重试、超时和错误处理器不是外围模板代码，而是 LangGraph 节点级执行语义的一部分。

How

节点失败后先按策略重试；超时被视作瞬时失败；重试耗尽时把失败上下文写入 checkpoint 并调度处理器。

Node attempt模型、工具或确定性逻辑的一次执行
→
Retry / timeout只对可恢复错误或卡住的尝试重新调度
→
Checkpoint失败状态作为 graph run 状态的一部分持久化
→
Error handler带着节点名和异常进入补偿、降级或通知路径

三种策略贴在节点旁边，容错才不会变成散落的模板代码

文章强调 LangGraph 控制 graph 的执行，因此也适合控制每个步骤失败时发生什么。策略配置和业务节点放在同一个 add_node 调用里：节点逻辑、重试、超时和失败后路径形成一个局部、可审计的单元。

RetryPolicy

对每次节点尝试应用指数退避、可选 jitter 和 retry_on 判定。默认只重试连接错误、HTTP 5xx 和若干瞬时错误，不默认重试 ValueError、TypeError 等常见程序错误。

TimeoutPolicy

给单次尝试设置硬性运行时长上限，或基于可观察进展的 idle 上限。超时触发后节点尝试会被取消，并抛出 NodeTimeoutError。

error_handler

只在重试耗尽后运行，接收包含失败节点名和异常的 NodeError，用于清理、告警、死信写入、模型降级或面向用户的失败路径。

超时是“卡住太久”的瞬时失败，重试策略决定它是否值得再试

文章把 timeout 解释成瞬时失败的特殊情况：不是函数立刻报错，而是一次尝试长时间没有完成或没有可观察进展。没有显式超时，卡住的 HTTP 调用或冻结的子进程可能让整个 graph run 无限挂起。

run_timeout 是硬上限

单次节点尝试超过指定 wall-clock 时间就被取消，适合明确不愿等待超过 N 秒的步骤。

idle_timeout 看进展

channel writes、streamed chunks、child task events、LangChain callback events 等信号会刷新空闲计时；活跃流式输出不会被误杀。

可用 heartbeat 显式保活

如果节点内部能主动发出进度信号，可以用 heartbeat 刷新策略，区分真正卡死和仍在推进的长流程。

错误处理器的关键，是重试耗尽后的原子转移

文章最重要的运行时细节在这里：当原节点失败时，LangGraph 会把 ERROR 写入 checkpoint，并在同一步调度 handler 作为新执行项。如果宿主进程在 handler 中途崩溃，下一次恢复会重新调度 handler，而不是回到已经失败的原节点。

这让失败处理不只是 try/except 的语法糖，而是可恢复执行的一部分：流程一旦进入失败分支，就能在 checkpoint 语义下继续完成清理或补偿。
触发时机

只在 retries exhausted 后触发；每次异常都要执行的逻辑仍然应放在节点内部。

失败上下文

handler 可从 NodeError 读取失败节点名与异常对象，从而决定补偿范围或降级路径。

递归边界

error handler 不能再配置另一个 error handler，避免无限递归式失败处理。

SAGA 例子说明：不是重试整个流程，而是补偿已经产生的副作用

原文用航班预订解释多步骤副作用：预留座位、处理支付、出票分别调用外部系统。天真地重试整条链路会留下坏状态；正确做法是每一步单独重试，某一步重试耗尽后，只撤销已经完成或状态未知的步骤。

Reserve seat

座位预留是外部副作用；后续支付或出票失败时，补偿节点需要知道它是否已经完成。

Process payment

支付失败不能简单重跑全部流程；重试耗尽后需要进入失败事件、通知或退款相关路径。

Issue ticket

出票失败时，checkpoint 中的步骤状态决定补偿节点撤销哪些已执行动作。

LangGraph 的组合价值在于：默认重试策略可作用到所有常规节点，任一节点耗尽重试后原子转到统一的 compensate 节点，并靠持久状态判断哪些步骤需要撤销。
