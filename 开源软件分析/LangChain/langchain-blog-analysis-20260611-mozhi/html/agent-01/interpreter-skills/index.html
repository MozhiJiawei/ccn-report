Why

只靠文字说明包装流程时，agent 在长任务中容易跳步、压缩流程或临场改写实现。

What

Interpreter skills 把 skill 变成“说明 + TypeScript API”，让确定性部分进入可测试代码，模型只负责判断何时调用和如何使用结果。

How

SKILL.md 继续负责发现与约束，index.ts 暴露模块函数；agent 在解释器里 import 后执行，函数可处理状态、工具结果和 subagent 调度。

它把“照说明做”改成“调用已知 API”。

普通 skill 告诉 agent 如何执行流程，核心行为仍依赖模型逐步遵循说明。Interpreter skill 则把固定步骤放入模块，降低同一流程每次被重新发明的概率。

Repo triage 展示了代码化流程的价值。

文章中的 GitHub triage routine 会获取开放事项、为每项生成浓缩描述、排队聚类并返回结构化结果。模型不需要在上下文里背着 300 个中间状态前进。

可评估性也更具体。

prompt-only 流程只能问“看起来有没有遵循说明”；interpreter skill 可以问 agent 是否调用了预期函数、是否传入正确输入、返回结构是否符合预期。

解释器状态让技能能处理数据而不是堆 stdout。

CSV 示例里 parse、join、filter、validate、summarize 都是 skill 模块操作，agent 负责组合，skill 作者负责这些动词的确定含义。
