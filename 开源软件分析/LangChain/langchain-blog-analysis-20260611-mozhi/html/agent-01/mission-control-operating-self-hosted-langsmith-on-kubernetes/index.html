Why

自托管 LangSmith 带来基础设施控制权，也把 Helm、kubectl、日志、dashboard 和支持脚本的切换成本交给平台团队。

What

Mission Control 是集群内运行的 LangSmith 运维层，不需要 ingress、外部控制平面或额外数据库。

How

它读取 Kubernetes primitives，再提供配置编辑、preflight、health、release、assistant、alerts、search、数据库检查和 diagnostic bundle 等 LangSmith-aware 工作流。

它没有替代 Kubernetes，而是给 LangSmith 运维加上下文。

Mission Control 仍围绕 Helm、pods、services、namespaces、logs 和 events 工作，只是把这些资源组织成回答“LangSmith 是否健康、哪里失败”的界面。

配置和发布前检查减少低级部署失败。

Quick Start 生成最小 values.yaml，Helm values editor 支持 simple/advanced、secret masking 和安全 diff；preflight 检查 node capacity、Kubernetes version、DNS、storage class、quota 等常见问题。

Health、release 和 alert 视图服务日常运营。

operator 可以看 pod CPU/memory、service readiness、live logs、network topology、PVC pressure、chart versions、release history 和 rule-based alerts。

诊断能力面向受限环境。

全局搜索跨 logs、descriptions、events、releases 和 alerts；数据库检查可发现 Redis、PostgreSQL、ClickHouse 并运行受控查询；diagnostic bundle 打包 logs、metadata、describe 和 event timeline。
