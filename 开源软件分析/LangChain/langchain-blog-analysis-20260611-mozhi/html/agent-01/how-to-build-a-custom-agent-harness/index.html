How to Build a Custom Agent Harness

Why：agent 的效果取决于 harness 是否把工作需要的上下文、工具和环境交给模型。What：create_agent 是 LangChain 的最小 harness 原语，预置较少、可定制空间大；middleware 是定制 agent loop 的核心接口。How：每个 middleware 负责一个 concern，在模型调用、工具调用、启动、结束和 stream 处理点组合起来，形成贴合具体工作场景的 harness。

Why

有用的 agent 不是只靠强模型，而是要在每一步拿到适合请求场景的上下文、工具、状态和约束。

What

create_agent 是 LangChain 的最小 harness 原语，预置较少、可定制空间大；middleware 是定制 agent loop 的核心接口。

How

每个 middleware 负责一个 concern，在模型调用、工具调用、启动、结束和 stream 处理点组合起来，形成贴合具体任务的 harness。

base harness 只是模型调用工具的循环。

文章先把 agent 简化为 model、tools、system_prompt 构成的 loop。create_agent 保留这个核心，而不是预先装入 memory、sandbox、context management 等完整栈。

middleware 是把工作需求接入 loop 的位置。

确定性逻辑、策略执行、动态换模型、消息压缩、工具注册与清理、状态追踪和 stream 转换，都可以在不同 hook 上由 middleware 处理。

task-harness fit 决定最终可用性。

客服 agent、长时 coding agent、GTM agent、no-code agent builder 需要不同的上下文和失败处理。文章的结论是：最好的 agent 是 harness 与工作紧密匹配。
