Your harness, your memory

如果 harness 被封闭在 API 后面，agent memory 也会一起被锁住。

核心观点：Why: agent memory 决定体验是否持续变好，但 memory 不是可随意替换的插件。What: 文章主张 harness 和 memory 绑定在一起，封闭 harness 会把长期记忆、压缩摘要和上下文策略锁进单一平台。How: 它从 Agent = Model + Harness 出发，比较 stateful API、闭源 harness 和完整托管 harness 的可见性与迁移风险。

文章的主张集中在这三点

这些子观点都服务于首屏结论，帮助读者快速抓住文章的判断框架。

01

Harness 不会被模型完全吸收

文章用 Claude Code 泄露代码规模和 API 内置 web search 说明，模型外仍有大量 orchestration。

02

Memory 是 context/state 管理方式

短期消息、工具结果、长期记忆读写都依赖 harness 的上下文策略。

03

闭源 harness 会制造迁移成本

stateful API 和 server-side compaction 会把线程状态或压缩摘要锁在提供商生态里。
