The Anatomy of an Agent Harness

Harness 是模型之外让 agent 真正工作的全部系统。

核心观点：Why: 原始模型不能持久记忆、访问实时知识、搭环境或执行复杂工作。What: 文章把 agent 定义为 Model + Harness，harness 是模型之外的代码、配置和执行逻辑。How: 它从期望行为倒推组件：filesystem、sandbox、tools、skills、MCPs、planning、subagents、middleware 和约束共同把模型智能变成 work engine。

Why原始模型不能持久记忆、访问实时知识、搭环境或执行复杂工作。
What文章把 agent 定义为 Model + Harness，harness 是模型之外的代码、配置和执行逻辑。
How它从期望行为倒推组件：filesystem、sandbox、tools、skills、MCPs、planning、subagents、middleware 和约束共同把模型智能变成 work engine。

文章的主张集中在这三点

这些子观点都服务于首屏结论，帮助读者快速抓住文章的判断框架。

01

Harness 是模型外的一切执行系统

如果不是模型，就是 harness；raw model 只有被包装进状态、工具、反馈环和约束后才成为 agent。

02

组件来自模型能力缺口

模型不能天然维护 durable state、访问实时知识或安装包完成工作，这些都由 harness 提供。

03

Harness engineering 是行为到机制的映射

想要 break down objectives、delegate work、enforce constraints，就设计 planning tools、subagents 和 middleware。
