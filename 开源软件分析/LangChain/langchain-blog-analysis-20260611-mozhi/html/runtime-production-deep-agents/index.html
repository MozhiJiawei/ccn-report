生产化的第一条件是运行可恢复

长任务失败时，如果只能重跑整个 agent，demo 可以接受，生产系统不能接受。原文的 crash recovery 图直接支撑 durable execution 是 runtime 底座。

Checkpoint 把 agent run 从“一次请求”变成“可恢复状态机”

文章首先解决的不是模型能力，而是长任务运行可靠性。

图中展示进程在中途失败后，runtime 从已保存的 checkpoint 继续执行。这个机制支撑后文的人类中断、并发运行和长期任务调度，因为它们都依赖“暂停后还能回到同一状态”。

Runtime 的控制点包住模型和工具

原文的 agent lifecycle 图说明 middleware 不是外围插件，而是嵌入 agent 生命周期的控制点。

Middleware 让安全、上下文工程和模型切换进入主路径

before_agent、before_model、wrap_tool_call、wrap_model_call、after_model、after_agent 这些节点决定了 runtime 能控制什么。

这张图支撑文章对 middleware 的描述：动态模型选择、PII 过滤、摘要压缩、工具调用包装和 guardrails 都不是散落的回调，而是围绕 agent run 的生命周期插入。

记忆不是聊天记录，而是跨运行的状态层

原文把 memory 放在 runtime 能力里，是因为生产 agent 需要跨 thread 和跨任务保留可复用信息。

Thread state 管当前任务，long-term memory 管跨会话积累

这一区分让 agent 可以同时处理短期上下文和长期用户/任务事实。

图中把 short-term memory、long-term memory 和 recall 路径分开，支撑文章对 persistence 与 memory 的拆分：保存 run 状态只是第一步，跨 thread 的 store 才能让 agent 形成长期连续性。

人工审批能进入同一条运行链路

HITL 的关键不是弹出确认框，而是在工具执行前把 run 中断到 checkpoint，再按审批结果继续。

Interrupt checkpoint 让高风险动作可审阅、可修改、可恢复

发邮件、付款、改数据库这类动作需要人类参与，但不能破坏 agent 的运行状态。

图中展示工具调用前的 interrupt 和 checkpoint，支撑文章对 human-in-the-loop 的定义：人类可以 approve、edit 或 reject，runtime 再从同一个状态继续执行。

这些机制最终收束成平台运行时

在原文机制之上，这张重构图只做一件事：把 durable execution、memory、middleware、HITL、streaming 和 deployment 放回同一个 runtime 层级里。

核心能力

文章的信息密度主要来自这些 runtime 能力，而不是模型效果指标。

Durable execution

agent 可在每个 step 被 checkpoint；进程宕机、网络失败或暂停后，可以从最近状态恢复，而不是从头重跑。

Persistence

平台自动保存 thread state；同一个 conversation 或长期任务可以跨请求继续推进。

Memory

短期记忆来自 thread，长期记忆进入 cross-thread store，用于个性化、事实沉淀和跨会话行为。

Human-in-the-loop

工具调用可插入人工审批、编辑或拒绝；适用于发邮件、付款、改数据库等高风险动作。

Streaming

支持 token、progress update、debug event、custom event 等不同粒度，让长任务可以被实时观察。

Middleware

在模型调用、工具调用和上下文构造周围插入逻辑，用于动态模型选择、PII 过滤、摘要压缩和 guardrails。

Observability

与 LangSmith tracing 结合，展示 agent steps、state changes、tool calls、latency 和错误路径。

Deployment controls

通过 deploy-time configuration、assistants 和 cron，把同一份图代码部署成不同配置和调度方式。

一次生产运行

文章反复强调的运行模型：长任务不是一次性请求，而是可暂停、可恢复、可审阅、可观测的状态机。

文章里的产品面

原文不仅讲 runtime primitives，也把这些能力落到开发、部署、观察和运行入口。

开发与调用入口

  • RemoteGraph SDK：从应用代码远程创建 thread、启动 run、流式读取事件。
  • HTTP API：用 REST 方式接入 LangGraph Platform。
  • LangGraph Studio：本地/云端调试 graph，观察状态和节点行为。
  • LangSmith UI：从 trace、deployment、assistant 配置进入运行和观察。

部署与运行控制

  • Deploy-time configuration：运行时注入配置，不把所有差异写死在代码里。
  • Cron jobs：让 agent 定时执行，如巡检、报告、同步和维护任务。
  • Sandbox：隔离代码执行、文件系统或工具环境，降低执行风险。
  • Task queues：让长任务和并发运行进入队列化调度。
