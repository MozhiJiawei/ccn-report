01 · Problem Framing

Agent 适配的瓶颈正在从“会不会”转向“流程是否稳定”

传统 prompt 太薄

单轮提示或一次性生成的 skill 缺少执行反馈闭环，不能系统吸收失败轨迹里的可复用规则。

模型权重又太重

闭源 frontier model 难以微调；开源模型微调也昂贵，且未必解决工具使用、证据收集和格式约束。

Skill 文档正好居中

它是外部文本状态，能承载程序性知识：搜索顺序、验证动作、工具策略、输出规范和失败模式。

论文图示把 skill space 类比为可优化空间：受控小步编辑沿验证误差下降，而大跨度 ad hoc 更新容易落入次优 skill。
Paper XML: abstract + introduction; Project page: Core Idea.
判断：SkillOpt 的对象不是知识注入，而是程序性适配
强调这不是“把论文知识塞进 prompt”，而是让执行流程本身有训练闭环。图 1 的右上角类比关系是这一页的视觉锚点。

02 · Mechanism

SkillOpt 用五步循环训练自然语言 skill

目标模型负责执行任务并产生轨迹；优化器模型只在训练期读取成功/失败证据，提出对 skill 文档的受控 add / delete / replace 更新。

1. Splittrain 产生 rollout evidence；validation gate 决定是否接受；test split 锁到最终报告。
2. Rollout → minibatch同一批轨迹被切成多个 minibatch，分别送给 optimizer model 反思。
3. Atomic edits每个 minibatch 生成 add / delete / replace 原子编辑，再做 batch-level merge。
4. Rank / clip候选编辑按当前 edit budget 排序截断，学习率调度控制每步移动幅度。
5. Gate / memory验证门控决定 accept/reject；rejected buffer 和 slow/meta update 反馈给未来优化。
论文 pipeline 图：从数据切分、rollout batch、minibatch reflection、原子编辑合并，到 validation gate、rejected buffer、slow/meta update。

05 · Relationship To Prompt Optimization

SkillOpt 和自动提示优化相邻，但优化对象更像“可部署程序文档”

自动提示优化

  • GEPA：利用 trajectory feedback 做 reflective prompt evolution。
  • TextGrad：把自然语言反馈当作文本梯度，推动文本变量改进。
  • 常见目标是 prompt、system design 或 agent configuration。

SkillOpt 的差异

  • 优化单一持久 skill document，而不是一次性 prompt。
  • 更新被限制为 bounded edit，并通过 held-out gate 接受。
  • 训练期记忆不进入部署期，最终 artifact 可审计、可版本化。

06 · Ablations & Transfer

有效性来自受控更新，而不是单纯让强模型重写 skill

学习率是 edit budget

消融显示默认 lr=4 在 SearchQA、SpreadsheetBench、LiveMath 上均强于 without lr，说明文本小步更新比无约束重写稳定。

拒绝记录也是训练信号

with rejected buffer 优于 without rejected buffer，失败候选会变成后续优化器的负反馈。

迁移验证 artifact 属性

跨模型、跨 harness、跨 benchmark transfer 都有正增益，支持 skill 是可复用程序文档而非过拟合日志摘要。

消融表：learning-rate form、rejected buffer、slow/meta update 三类控制均贡献稳定性。
Transfer 表：跨模型、跨 harness、跨 benchmark 均报告正向迁移。
证据边界：迁移实验支持相邻设置复用，不等于任意任务泛化
这页的核心是机制归因。不要把结果讲成“强模型自动写得更好”，而是强调 gate、budget、buffer、slow/meta update。

07 · Enterprise Implication

企业 Agent 工作流的入口不是“自动进化”，而是“可评测的技能资产”

先有 eval

SkillOpt 依赖 scored rollouts 和 held-out selection split。没有可重复评分的数据切分，就无法区分有效 skill 与漂亮改写。

再训 skill

适合表格、文档问答、工具调用、数学验证、操作规程等可以沉淀流程规则的任务。

最后审计部署

最终产物是 Markdown 文档，便于 code review、版本管理、灰度、回滚和跨模型迁移测试。

适合先试

  • 已有任务集、评分器或验收脚本。
  • 失败模式重复出现，且能被流程规则修复。
  • 希望减少推理期额外 agent 调用。

不要过度承诺

  • 论文结果仍在特定 benchmark / model / harness 范围内。
  • 训练成本取决于 rollout 数量和 optimizer model 调用。
  • 安全关键任务仍需要人工审阅和生产灰度。
后续 PPT brief 建议主线：SkillOpt 的真正价值不是“让 Agent 自己变聪明”，而是把 skill 从手写经验变成可训练、可验证、可审计、可迁移的软件资产。
