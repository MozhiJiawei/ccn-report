SlidingServe 优化vLLM调度，提升30%+

它不改模型和算子，而是在推理服务调度层优化请求排队、批次预算和超时风险控制；论文报告在 SLO 约束下，相对先进基线最高约 30% 的合格服务量提升。

30%+
相对 QoServe 的最高 goodput 提升口径；不是单请求推理速度提升。

方法：把“每轮塞满”改成“跨轮算账 + 批内取舍”

跨轮预算分配

SlidingChunker 同时看当前轮和下一轮 slack，用轻量 latency predictor 搜索更合适的 chunk budget。

批内请求选择

BatchConstructor 在违约风险出现时，保护 anchor request，再用动态规划选择额外请求集合。

vLLM 连续批处理的痛点

长 prompt prefill 容易堵住 decode；prefill 切太小又拉低 GPU 利用率。

数字口径

“30%+”应解读为相对先进 SLO-aware baseline 的最高 goodput 提升，不代表所有数据集、模型、负载都固定提升 30%。

落地复测边界

优先在长 prompt 占比高、prefill/decode 干扰明显、峰值容量紧张且 SLO 明确的服务上复测；短请求或宽松 SLO 场景收益可能收缩。
