2. 机制主轴：hybrid selector 先选 Top-K，再只验证活跃 KV

Figure 5 · original mechanism figure

Stage 1: draft generation & KV selection

draft model 的前瞻 attention 暴露未来草稿 token 可能需要的历史依赖。

Stage 2: sparse verification & update KV

target model 不再读取全量 KV，而是对压缩后的 verification set 做验证。

保底上下文 attention sinks + recent window 保护稳定上下文与局部连续性。
+
两路重要性信号 draft lookahead 覆盖“接下来可能重要”；target historical 覆盖“过去已经重要”。
→
SRH sparse estimation 离线找少量语义检索 heads，在线只用这些 heads 估计 criticality。
512active KV token budget

工程含义：PoC 优先复现 target-side selector + sparse verification path；不要先把资源花在重新训练或替换 drafter 上。

边界：Dustin 仍保留完整历史，通过 global indexing 选择验证阶段激活 token；降低的是活跃读取与 attention 计算成本，不直接降低完整 KV cache 显存占用。
复现 1: 先做本地延迟拆解

按 Figure 1 口径确认 16k/32k、batch 8/16 下 verification 是否主导。

复现 2: 验证 selector 与 SRH 成本

观察 criticality estimation 是否低于 full-cache self-attention，避免动态选择反噬收益。

复现 3: 用长文任务压质量边界

在 PG-19 / LongBench 或本地长上下文任务上扫 512 / 256 / 128 budget。
