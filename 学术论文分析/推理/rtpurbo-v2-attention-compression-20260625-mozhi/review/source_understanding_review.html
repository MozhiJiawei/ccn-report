主源：arXiv:2605.16928 v2，2026-06-08；解析产物：GROBID + Docling XML package

RTPurboV2 的核心不是换掉 Full Attention，而是把它“显式稀疏化”

论文主张：Full-attention LLM 内部已经存在可利用的稀疏结构，只需几百步后训练，就能把长上下文推理从全量注意力迁移到 head-wise sparse attention，并保持接近无损精度。

这一页只建立结论：RTPurboV2/RTPurbo 不是训练一个全新稀疏模型，而是从 Full Attention 模型中释放内生稀疏性。重点数字来自论文摘要与 Figure 1。

01 · 问题定义

问题对象：long-context inference 的 full attention 二次复杂度

长上下文瓶颈来自全头、全 token、全维度都在参与匹配

论文把低效拆成三个可压缩对象：哪些 head 需要长程，哪些维度承载召回，哪些 token 真正值得算。

Head 维度

分工把 attention heads 分成 retrieval heads 与 local/streaming heads。

→

Feature 维度

低秩用 16 维 indexer 做长程相关性检索，降低 QK 匹配成本。

→

Token 维度

动态用 query-dependent top-p 选择有效 token，而不是固定 top-k。

压缩对象论文中的处理方式要回答的问题
Head离线校准识别 retrieval heads；非 retrieval heads 不保留完整长程路径。长程信息是否只由少量头负责？
Feature训练低维 projection，保留 RoPE 低频语义信号。检索是否可以用低维索引近似？
Token解码阶段用动态 top-p sparse attention。每个 query 需要的 token 数是否高度变化？
这一页把注意力压缩对象讲清楚，避免泛泛说“压缩 attention”。RTPurbo 的对象不是 KV cache 全局剪裁，而是 head-wise、feature-wise、token-wise 的组合。

02 · Head-wise prior

Evidence: Figure 2, Figure 8, Section 3.1

少量 retrieval heads 决定长程召回，其余头天然更适合局部化

为什么能从 Full Attention 迁移？

  • 论文观察到 heads 已经出现功能分化：retrieval heads 关注远距离语义相关 token。
  • 离线校准给每个 query head 打 retrieval score，高分头保留长程检索路径。
  • 这让压缩从“全局稀疏化”变成“只保护少数关键头”。

Figure 2：retrieval head 会跨距离关注与 query 语义相关的区域。

Figure 8：Qwen3-Coder-30B-A3B 的 head-wise retrieval score，支持“少数头承担长程召回”的校准策略。

这页的关键不是说 15% 是普适常数，而是说明论文如何把 head 分工变成可操作的离线校准。不同模型 retrieval head 比例会变化，后面边界页会说明。

03 · Low-dimensional retrieval geometry

Evidence: Section 3.2, Table 2, Appendix ablations

长程检索主要依赖低频语义分量，16 维索引器承担候选召回

论文的机制链

  • RoPE 使 QK score 可分解为不同频率分量；高频分量对远距离位置更敏感。
  • 长程 retrieval 更需要稳定语义匹配，因此可压到低频主导的低维子空间。
  • 低维 projection 不是直接替代 attention 输出，而是作为 token indexer 先召回候选。

配置含义

论文配置里 token indexer 使用 hidden size = 16；结合 retrieval-head ratio、top-p 和 GQA group size，形成完整 sparse decode 配置。

Table 2：RTPurbo config。低维大小是理解 feature compression 的关键。

要点：低秩投影压缩的是“检索索引空间”，不是把最终 Value 聚合也粗糙低维化；这降低候选选择成本，同时保留后续 attention 计算的精度路径。
这里要把低维投影讲成人话：先用低维空间快速找候选，不等于低维生成最终答案。这个区分能避免把它误解成普通降维压缩。
Low-rank token indexer

04 · Query-dependent sparsity

Evidence: Table 1, Section 3.3

固定 top-k 会错配不同 query 的 token 预算，动态 top-p 更贴近注意力质量

为什么不是固定 top-k？

  • 同一序列里，不同 query 的注意力质量集中程度差异很大。
  • 固定 top-k 为困难 query 留不够 token，又会给简单 query 多算无效 token。
  • top-p 用累计 attention mass 控制召回质量，更像“保留足够证据”。

Table 1：固定 top-k 与 top-p 的对比；论文指出 top-16k 多算约 8k token，却只多恢复 3.8% attention mass。

策略优势风险RTPurbo 选择
top-k实现简单，token 数固定对 query/head/长度变化不敏感作为对照基线
top-p按注意力质量动态保留 token需要高效 kernel 处理变长候选作为 sparse decode 主路径
这页是 token 维度压缩的核心。动态 top-p 的价值不只是更省，而是在同样或更低计算下更好保护召回质量。
Dynamic top-p selection

05 · Method architecture

Evidence: Figure 4, Section 4

RTPurbo 的推理路径是“离线校准 + prefill 索引 + decode 稀疏选择”

Figure 4：RTPurbo 总体架构。图中把 head 校准、KV/索引保存、稀疏 decode 串成完整路径。

离线校准

识别 retrieval heads，并确定哪些头需要保留 full KV cache。

Prefill 建索引

对 retrieval heads 生成低维 token indexer，为长程匹配降本。

Decode 稀疏化

用动态 top-p 选 token，再通过硬件友好 kernel 执行 sparse attention。

这页让执行者知道系统路径。RTPurboV2 新闻里提到低秩投影、聚类、动态 top-p；论文当前 XML 主要支撑 RTPurbo 的低维 indexer 与动态 top-p 主线。

06 · Training adaptation

Evidence: Abstract, Appendix C, Figure 9

后训练成本低，是它区别于原生稀疏训练路线的关键卖点

两阶段适配

  • Stage 1：训练低维 projection，让 token indexer 学会复现长程召回。
  • Stage 2：端到端适配 sparse attention 路径，减少训推结构差异。
  • 论文强调只需要 few hundred training steps，而不是重新做 native sparse pretraining。

Table 5：reasoning benchmarks 精度对比。该表用于观察低成本适配后是否保留推理能力。

证据边界：论文摘要给出“few hundred training steps”；新闻解读进一步写作约 600 步、约 1M label tokens。Content Brief 阶段应区分论文数字与媒体解读数字。
这页先不把“600 步”作为论文强证据写死，因为当前论文摘要是 few hundred training steps，600 步来自外部解读。后续 brief 需要证据分级。
