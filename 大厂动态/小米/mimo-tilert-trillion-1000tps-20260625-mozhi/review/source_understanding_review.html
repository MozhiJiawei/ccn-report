Source Understanding · 2026-06-25

1000+ TPS 来自模型和系统同时改形

MiMo × TileRT 的官方叙事不是“某个 kernel 更快”，而是把 1.02T / 42B active 的 MoE 模型、专家 FP4、DFlash 块级投机解码和 TileRT 常驻执行模型绑成一条低延迟流水线。

1T+

官方称万亿参数模型；模型卡给出 backbone 1.02T / active 42B。

1000+

MiMo 与 TileRT 文均称在通用 GPU 上突破 1000 tokens/s。

8

MiMo 文称“一个标准 8 卡通用 GPU 节点”，但未公开 GPU 型号。

8 draft

DFlash mask block size 设为 8；不同场景平均接受长度约 3.18-6.30。

可用判断：这是一次“模型结构、量化、投机解码、执行 runtime”协同案例；不可直接判断：它与任意主流 serving 框架在同硬件、同 batch、同任务下的公平胜负。
来源：MiMo 官方博客；TileRT 官方博客；HuggingFace 模型卡。

Mechanism

速度提升链条：少搬参数、少跑轮次、少断流水

专家 FP4

只把 MoE experts 量化到 MXFP4，其他模块保持更高精度，先压低万亿模型 decode 的访存压力。

→

DFlash

draft 一次填充整块 mask token，再由 backbone 验证；block size 8，目标是让一次验证吞下更多 token。

→

TileRT

用常驻执行模型消除 operator boundary，把数据搬运、tensor compute 和通信拆成连续 tile pipeline。

为什么不是单点技术

MiMo 文明确说“不是单一技术突破”；TileRT 文也把 1000+ TPS 归因于模型与系统在硬件边界上的深度收敛。

为什么口径要保守

公开材料能证明官方实现与思路，但没有给出可复现实验矩阵；PPT 中应把 1000+ TPS 写成官方发布结果，而非通用可迁移基准。

Model Side · FP4

FP4 只打 MoE experts，换取带宽收益而非全模型压缩

核心判断

MiMo/HF 均强调“expert-only FP4”：专家占参数大头且更耐量化，所以只对 experts 用 MXFP4；attention projections 与其他模块保持更高精度。

质量证据

图表显示 FP4 与 FP8 在 agent/code benchmark 上接近；适合表达为“接近 FP8 基线”，不宜写成“无损”。

图源：MiMo 官方博客 / HF 模型卡，FP4 experts-only 与 FP8 benchmark 对比；HF 还点名每层 attention o_proj 排除在 FP4 外。

Model Side · DFlash

DFlash 用 target hidden states 引导 block diffusion draft

图源：DFlash 论文 Figure 2。蓝色为 fused target context feature，黄色为 target decode token，绿色为 mask token。

推理路径

target model 先产生已确认 token 与 hidden features；DFlash 把多层 hidden states 融合成 context feature，再注入每层 draft layer 的 Key/Value cache。

为什么更像“适配器”

draft model 不是从零推理未来 token，而是借 target 表征做条件生成；论文称这让小 diffusion drafter 兼得并行 draft 与较高接受率。

和 MiMo 的映射

MiMo 模型卡给出 5-layer BF16 drafter、captured layers [0, 15, 31, 47, 69]、block size 8，正对应图中的 target feature 注入和 block draft。

DFlash · Training Attention

训练时用 anchor + mask block 对齐推理时的验证循环

训练样本怎么构造

论文不是把 response 均匀切块，而是随机采样 clean anchor token，把 anchor 后面的若干位置变成 mask，让 drafter 学“从已确认 token 开始并行预测下一块”。

attention mask 约束

同一 block 内可双向看，且能看对应 target context feature；跨 block 被 invisible tokens 隔离，避免训练时偷看不该看的未来信息。

早错更贵

loss 对 block 前部 token 加更高权重，因为 speculative verification 只接受连续前缀；第一个错 token 会截断后续 token 的收益。

图源：DFlash 论文 Figure 4。蓝色 target context feature，黄色 clean token，绿色 mask token，白色 invisible token。

DFlash · Performance & Boundary

DFlash 的优势来自“draft latency 不随 token 数线性增长”

图源：DFlash 论文 Figure 1，Qwen3-8B / Transformers backend；不是 MiMo 8-GPU 1000+ TPS benchmark。
图源：DFlash 论文 Figure 3，展示不同 draft token 数下的 draft latency。
要点对 MiMo deck 的含义
AR drafter 要逐 token 生成，draft cost 随 speculative token 数增加解释为什么传统 speculative decoding 在极低延迟场景仍有串行瓶颈
DFlash 一次 forward 预测整块 mask token解释 MiMo “block size 8 / 接受长度 6.30”如何转化为 fewer backbone rounds
论文结果基于 Qwen3 等模型，MiMo 是工程落地变体不能把论文 6× speedup 直接等同于 MiMo 1000+ TPS；两者是机制支撑关系

MiMo DFlash · Acceptance Length

MiMo 里的 DFlash 收益对 coding/agent 更明显

接受长度

场景平均接受长度含义
WebDev / Coding6.308 个 draft token 中平均可接受 6 个以上
Math5005.56推理场景接受长度较高
HumanEval4.54代码生成中等偏高
SWE-Bench / Agent4.29agent 场景仍有端到端收益空间
MT-Bench3.18开放对话接受率较低，官方承认泛化仍在优化

读法

接受长度不是“draft 输出几个 token”，而是 target verifier 确认的连续前缀长度；block size 8 的情况下，接受长度越接近 8，target backbone 每轮验证摊到的 token 越多。

MiMo 官方中文文把 coding 场景写为 6.30，部分样本最高 7.14；HF 模型卡还列出 HumanEval、MT-Bench 等更细分项。

因此 PPT 应强调“场景相关”：coding/agent 更受益，开放对话不能套用最高接受长度。

System Side · TileRT

TileRT 的关键是消除微秒级 operator boundary

图源：TileRT 官方博客，传统执行模型的 operator boundary / execution gap。

第一跃迁：执行模型

传统逐算子 launch 在 ultra-low latency 下暴露 host launch、hardware sync、global memory round-trip 等间隙；Persistent Engine 让整条流水线常驻硬件内部。

第二跃迁：模型系统共设计

RMSNorm、RoPE、KV cache writes、metadata 等非核心操作也会吞掉微秒预算；因此 FP4、DFlash、SWA window 和 verification cost 需要共同权衡。

部署线索

HF 模型卡给出 SGLang 示例：DFLASH、speculative-num-draft-tokens 8、ep-size 16、tensor-parallel-size 16、data-parallel-size 2、context-length 65536。

Review Gate

后续 brief 的建议基线

可强表达

这是模型-系统 codesign，而非单点 kernel 或单一投机解码技巧；官方原文与模型卡互相支撑。

可中等表达

FP4 experts-only 与 DFlash 是把 1T decode 成本压下来的两条模型侧主线；TileRT 负责把微秒级间隙压到 runtime 层。

必须弱表达

1000+ TPS 的硬件与 benchmark 口径不完整，不能写成“公开可复现的行业通用基准”或“公平超越某框架”。

进入 Content Brief 前要保持的边界建议措辞方向
硬件配置未公开 GPU 型号“在官方称标准 8 卡通用 GPU 节点上实现”，不要补猜 H100/B200/A100。
TPS 统计口径未完整公开“官方发布的 decode/output speed 超 1000 tokens/s”，不要与 vLLM/TensorRT-LLM 横向排名。
DFlash 对场景敏感突出 coding/agent 的高接受长度，同时说明开放对话接受率较低。
