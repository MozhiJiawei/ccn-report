01 / Core Reading页面级判断

Subagent 的核心价值是降低主会话污染，而不是让 Codex 自动多开

文档把问题定义为主线程被探索笔记、测试日志、堆栈和命令输出淹没后可靠性下降；subagent 的解法是让这些噪声工作在并行线程中完成，只把 distilled summary 带回主会话。

问题入口：上下文噪声

长上下文仍有边界；中间输出越多，需求、约束和决策越容易被埋掉。

→

机制：并行委派

Codex 启动专门 agent 分别探索、测试、分析日志或拆解大材料。

→

回流：摘要而非原始噪声

主线程保留需求、决策和最终输出，接收子任务总结而非完整过程。

证据锚点：原文指出 context pollution / context rot，并列出 “keep the main agent focused”“run specialized subagents in parallel”“return summaries”。
02 / Operating Boundary适用边界

优先并行读任务；写任务并行会把收益换成协调成本

文档给出的默认策略很明确：探索、测试、triage、summarization 这类 read-heavy 工作适合并行；多个 agent 同时改代码会制造冲突，增加协调开销。

适合探索与阅读

多文件扫描、文档拆解、大日志初筛，可以独立完成并返回归纳结果。

适合验证与 triage

测试失败定位、安全风险扫描、缺口整理，天然能分给不同视角。

谨慎并行写入

同时编辑代码会带来文件冲突、行为覆盖和结论合并成本，需要更强协调。

证据锚点：原文建议从 read-heavy tasks 入手，并提醒 write-heavy workflows 会 create conflicts 和 increase coordination overhead。
03 / Trigger Contract触发与提示词

Subagent 需要显式指令，prompt 要写清拆分方式、等待策略和回收格式

Codex 不会自动 spawn subagents；只有用户明确要求 subagents 或 parallel agent work 时才应使用。好的指令不仅说“并行”，还要定义每个 agent 的任务边界、是否等待全部完成，以及最终如何汇总。

Prompt 要素 应该说明什么 为什么重要
拆分方式 按风险、文件、资料段落、测试类型或审查角色划分。 避免多个 agent 重复劳动，保证结果互补。
等待策略 是否等所有 agent 完成后再继续，或先处理关键路径结果。 决定主线程何时合并，防止半截结论进入决策。
回收格式 要求按类别、文件引用、严重度或行动项返回摘要。 把并行输出压成可执行判断，避免重新污染主线程。
证据锚点：文档示例要求为 security risks、test gaps、maintainability 各 spawn 一个 subagent，并等待三者后按类别和文件引用总结。
04 / Model Routing模型与推理强度

模型选择按任务深度分层，reasoning effort 按边界复杂度加码

如果不指定模型或 reasoning effort，Codex 可以自行平衡智能、速度和价格；需要精控时，用户可在 prompt 或 agent file 中指定 model 与 model_reasoning_effort。

配置项 文档建议 适合的 subagent 工作
gpt-5.5 多数 Codex 任务从这里开始；适合 demanding agents。 模糊、多步、需要规划、工具使用、验证和较长上下文跟进。
gpt-5.4 当 workflow pin 到 GPT-5.4 时使用。 强编码、推理、工具使用和较广工作流。
gpt-5.4-mini 速度和效率优先，适合 lighter subagent work。 探索、read-heavy 扫描、大文件审阅、支撑材料处理。
gpt-5.3-codex-spark ChatGPT Pro 下用于近实时文本迭代，研究预览。 延迟比广泛能力更重要的 text-only 任务。

high

复杂逻辑追踪、假设检查、边界案例、安全或审查型 agent。

medium

多数任务的平衡默认值。

low

任务直接、速度优先时使用。

证据锚点：原文分别列出模型选择和 reasoning effort，并说明更高 reasoning effort 会增加响应时间和 token 使用，但可改善复杂任务质量。

页面标题候选：Subagent 把噪声工作移出主线程

标题说明：探索、日志、测试和大材料拆解由并行 agent 处理，主线程只接收摘要。

  • 上下文保洁：减少中间输出淹没需求和决策。
  • 并行拆解：独立任务可同时推进并返回 distilled takeaways。

页面标题候选：Subagent 要显式触发，读任务优先

标题说明：Codex 不自动 spawn；prompt 要写明拆分、等待和汇总格式。

  • 触发清楚：用 spawn、delegate、one agent per point 等直接指令。
  • 写入谨慎：并行改代码会增加冲突和协调成本。
